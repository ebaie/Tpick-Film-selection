# 快调选片 · Tpick-Film selection

面向摄影师的 Windows 本地自动选片工具：一键识别并标记模糊、虚焦、过曝、欠曝、闭眼的照片，帮你从成百上千张里快速筛出合格片。

当前版本 **V2.01**（程序版本 `2.0.1`），内置 RS 插件 **v1.4**。GitHub 提供便携版，Microsoft Store 版本需经微软审核后更新。

- **Microsoft Store（推荐，免费）**：<https://apps.microsoft.com/detail/9PN3FB25RBF6>
- **Windows 便携版**：见本仓库 [Releases](https://github.com/ebaie/Tpick-Film-selection/releases)，下载 EXE 后直接运行，无需安装 APPX 发布者证书

## 主要功能

- 自动检测模糊 / 虚焦 / 过曝 / 欠曝 / 闭眼
- 显示每张照片被标记的原因，二次确认后再导出
- 「合格 / 废片 / 复核」分开筛选；待复核照片不随合格片批量导出，可右键标为合格、废片或放入复核
- 单击改判，双击仅放大查看，保留照片判定和当前筛选状态
- 批量分析与导出（JPEG / PNG / WEBP / TIFF）
- 完全本地运行，照片不上传云端
- 支持插件扩展（主题与自定义检测规则）

## 闭眼检测是怎么做的

口径：**只有双眼都可见地闭合才算「闭眼」**；单眼眨眼不会直接标记为双眼闭合。小眼睛、遮挡、极端侧脸或模型信号冲突会显示「眼部需复核」，而不是强行判为睁眼或闭眼。未检测到人脸单独记录。

处理链（全部在本地 CPU 运行，无网络请求）：

1. **MediaPipe Face Landmarker**（Apache-2.0，`models/face_landmarker.task`）最多定位 8 张人脸，输出 478 点网格与 52 个表情系数；对画面中较小的人脸进行局部再定位，提高眼睑定位的分辨率
2. 用像素坐标、沿眼轴垂直方向计算三组眼睑距离的中位数，消除照片比例与头部倾斜对开合度的影响；按人物左右眼正确对应 **eyeBlinkLeft / eyeBlinkRight**
3. 从原图采样旋转校正后的左右眼框（三档余量投票），避免只从整图缩略画布裁眼睛。送入 **OCEC 单眼开闭分类器**（MIT，`models/ocec_*`）——该模型已转换为自有权重格式，由 `renderer/ocec.js` 以**纯 JavaScript** 推理，**不依赖 ONNX Runtime**；OCEC 输出的是睁眼概率
4. 6 个特征送入**单调逻辑回归融合模型**（`models/eye_ensemble_6f.json`，标准阈值 0.88），输出双眼闭合概率。约束权重方向，避免更大的眼睛开合度反而提高闭眼概率
5. 逐只眼检查眼睑间隙、眨眼分数和眼框投票。融合分数超过阈值仍需双眼都有闭合证据；双眼同时有闭合证据且定位可靠时，支持阈值为 `max(0.65, 标准阈值 - 0.12)`。单眼睁开、可见眼睑间隙或信号冲突不被融合分数直接覆盖。多人照片任一人明确双眼闭合会提示闭眼，否则未确定的人脸与达到检测上限的照片提示复核
6. 调节阈值后逐张人脸重判缓存结果；人工改判优先保留。没有其他明确废片原因的眼部不确定照片进入「复核」，统计与 CSV 单独显示，人工标为合格后才参与批量导出。已有明确模糊、曝光等问题的照片仍归废片并保留眼部复核提示；单独导出属于用户明确选择，不受批量筛选限制

下面保留 **RS v1.1 阶段融合权重的历史验证**：在自建数据集的 349 张可用标注照片（313 张睁眼、36 张闭眼，另有 25 条跳过标注）上按源图 SHA256 分组的五折交叉验证，尚未应用运行时质量和单眼保护规则。v1.4 沿用这些权重，但增加了原图眼框、局部定位、多人检测和复核规则，历史表格不能作为 v1.4 的准确率：

| 指标 | 数值 |
|---|---|
| 准确率 | 0.963 |
| 闭眼精确率 | 0.829 |
| 闭眼召回率 | 0.806 |
| F1 | 0.817 |

同一历史验证划分下，旧模型在默认阈值 0.80 时有 8 张睁眼误报、7 张闭眼漏报；六维模型标准阈值 0.88 时为 6 张睁眼误报、7 张闭眼漏报。此数据集较小，阈值经过交叉验证选择，不能当作新照片上的准确率保证；还有少量疑似错误或非真实人脸标注，原始标注未被改写。

v1.4 本地运行检查结果写入 `test-output/eye-runtime-v1.4.json`，分别记录睁眼、闭眼和待复核，以及用户提供的四张误判样本。此运行检查复用了训练数据，属于回归检查，并非独立准确率评估；复核不能算成正确的睁眼或闭眼预测。

边界说明：这是**提示性**判定，界面支持一键改判（单击照片）。「未标记闭眼」不等于确定睁眼，眼部需复核的照片会保留人工复核提示。

双击查看不会改判；单击会等待双击判别间隔后才生效，避免在「合格」筛选下首击就移除照片。

## 开发与构建

```bash
npm install        # 安装依赖（@mediapipe/tasks-vision、electron 等）
npm start          # 开发运行（prestart 会自动把 MediaPipe 运行时复制到 renderer/vendor/mediapipe/）
npm test           # 单元测试 + 自研推理器与 ONNX Runtime 的一致性回归测试
npm run dist-store # 打包 APPX（商店提交用）
```

- MediaPipe 的 WASM 运行时约 13MB，属第三方二进制，**不进入 git 历史**；由 `npm run vendor`（`scripts/fetch-runtime.js`）从 node_modules 复制。
- `test/ocec-parity.test.js` 用真实眼部裁剪比对自研 JS 推理器与 ONNX Runtime 的输出（要求最大偏差 < 1e-4）。
